# PartPilot AI — step-by-step setup and deployment

This guide deploys the **LLM gateway**. The competition **controller** is still submitted to the organizer's runner and must be adapted to the exact `API.md` contract. These are separate deployment targets.

## A. Requirements

- Windows 10/11, macOS, or Linux.
- Python 3.10 or newer (Python 3.11 is a good default for this scaffold).
- VS Code (recommended) or another editor.
- Git and a GitHub account.
- A Gemini API key from Google AI Studio.
- A Render account or another HTTPS hosting provider.
- The organizer's real `API.md`, `OBSERVATIONS.md`, gateway example and local runner.

The example Gemini model is `gemini-2.5-flash`. Verify that the model is available to your API project. Set `GEMINI_MODEL` to another currently available model if your project does not have access. Model availability and quotas can change.

## C. Create a Python virtual environment (Windows PowerShell)

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation for this terminal, use this temporary process-only setting:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

For macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## D. Run the local safety tests

From the project root:

```powershell
pytest -q
```

Expected result for this scaffold:

```text
9 passed
```

These tests cover the generic internal safety utilities. They do **not** prove compatibility with the organizer's private action protocol. After the organizer files are available, add tests for each official action and run the organizer's checker.

## E. Obtain and protect a Gemini API key

1. Open Google AI Studio: https://aistudio.google.com/app/apikey
2. Sign in and create an API key for your project.
3. Copy it once and store it in a password manager or a private team secret store.
4. Do not paste it into source code, GitHub, screenshots, or the organizer's submitted `solution.py`.
5. Check the model and quota available to your API project.

The model is configured with `GEMINI_MODEL`; the example uses `gemini-2.5-flash`. Change it through an environment variable if needed.

## F. Run the LLM gateway locally

In PowerShell, set the variables in the same terminal session:

```powershell
$env:GEMINI_API_KEY = "PASTE_YOUR_GEMINI_KEY"
$env:GATEWAY_TOKEN = "MAKE_A_LONG_RANDOM_SECRET"
$env:GEMINI_MODEL = "gemini-2.5-flash"
```

Generate a strong token rather than using the example string. One way to create one with Python is:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(40))"
```

Start the service:

```powershell
python gateway/server.py
```

Open a second PowerShell terminal and test health:

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health
```

Expected response:

```json
{
  "status": "ok",
  "service": "partpilot-gateway"
}
```

The health endpoint proves the web process is running; it does not prove model inference. Test authenticated inference next:

```powershell
$headers = @{ "X-Gateway-Token" = $env:GATEWAY_TOKEN }
$body = @{
  payload = @{
    requests = @(
      @{ request_id = "DEMO-1"; text = "Need 12V USB-C, at least 10W." }
    )
    parts = @(
      @{ part_id = "DEMO-P1"; description = "12V USB-C adapter rated 20W"; snapshot_stock = "available"; freshness = "recent" }
    )
    purpose = "Connectivity test only; do not dispatch."
  }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod `
  -Uri http://127.0.0.1:8080/v1/plan `
  -Method Post `
  -Headers $headers `
  -ContentType "application/json" `
  -Body $body
```

Expected response includes:

```json
{
  "plan": { "requests": [], "recommendations": [] },
  "model": "gemini-2.5-flash",
  "inference": "real"
}
```

The exact plan contents are generated by the model and can differ. If the request fails, check that the key is valid, the model is enabled for the project, quota is available, and the environment variables are set in the terminal running `gateway/server.py`.

## G. Deploy the gateway to Render (recommended quick route)

1. Create a private GitHub repository named `partpilot-ai`.
2. From the project root, commit and push the scaffold (see section H).
3. Sign in to Render: https://dashboard.render.com/.
4. Choose **New → Blueprint** if using `render.yaml`, or **New → Web Service** and select the GitHub repository.
5. If configuring manually, use:

   - Runtime: Python 3
   - Build command: `pip install -r requirements.txt`
  - Start command: `python gateway/server.py`
   - Health check path: `/health`

6. Add these environment variables in the Render service's Environment page:

   - `GEMINI_API_KEY` = your Gemini API key
   - `GATEWAY_TOKEN` = the same long random secret used by the controller
  - `GEMINI_MODEL` = `gemini-2.5-flash` (or a model available to your project)

7. Deploy the service and wait for Render to report that the deploy succeeded.
8. Copy the service URL, for example `https://partpilot-llm-gateway.onrender.com`.
9. Test `https://YOUR-SERVICE.onrender.com/health` in a browser.
10. Set `PARTPILOT_GATEWAY_URL` to the service URL in the controller runtime if you use `gateway_client.py`.
11. Set `GATEWAY_TOKEN` to the exact same secret in the controller runtime.
12. Test the real `/v1/plan` endpoint using `scripts/check_gateway.py` (see below).

Render terminates public TLS and redirects HTTP requests to HTTPS for web services. It expects the app to bind to `0.0.0.0` and the port in `$PORT`. Free web services can spin down after inactivity, so a cold start may delay the first model call. For a timed competition, test the deployed endpoint well before the submission window and use an always-on plan/host if cold-start delay would risk the deadline.

## I. Test the deployed gateway

Set controller-side variables in a fresh PowerShell terminal:

```powershell
$env:PARTPILOT_GATEWAY_URL = "https://YOUR-SERVICE.onrender.com"
$env:GATEWAY_TOKEN = "THE_SAME_LONG_RANDOM_SECRET"
python scripts/check_gateway.py
```

The script should print a JSON response with `"inference": "real"`. This is a connectivity smoke test, not a competition evaluation.

## J. Connect the gateway to the organizer's controller

This is the essential integration step that cannot be completed from the challenge summary alone.

Read the organizer's exact `API.md`, `OBSERVATIONS.md`, controller example and gateway example. Map the documented fields into `partpilot/protocol_adapter.py`:

1. Identify the precise observation field containing requests and catalogue records.
2. Identify the exact `op:llm` request format and gateway endpoint requirements.
3. Identify how the returned model text is delivered back to `decide()`.
4. Identify exact action names and argument fields for inspect, clarify, verify, dispatch and escalate.
5. Identify which returned observations indicate successful tool execution.
6. Implement `decide(observation, state)` so it follows the organizer's lifecycle exactly.
7. Persist evidence, budget, action count, reserved part IDs and decisions in JSON-serializable `state`.
8. Do not assume an action succeeded until the next observation or protocol response confirms it.

**Do not replace the organizer's `op:llm` mechanism with a direct HTTP call unless its API explicitly says to do so.** The optional `gateway_client.py` is for a conventional `/v1/plan` HTTP integration; the organizer may require a different envelope and callback lifecycle.

## K. Run the organizer's local simulation

Use the exact command from the organizer's current `DEVELOPMENT.md`. The supplied challenge summary shows:

```powershell
python local_runner.py solution.py smoke.json --mock
```

Then run training and practice exactly as instructed in the current development guide. Keep public training and practice roles separate; do not use practice labels as training labels if the rules prohibit it. Inspect diagnostics after each run.

## L. Freeze and submit

Before upload:

- Run `pytest -q`.
- Run the organizer's smoke test.
- Run every permitted public training/practice check.
- Confirm all six requests receive a final decision.
- Confirm the tool budget never exceeds 14 units.
- Confirm the action count never exceeds 60.
- Confirm no part ID is dispatched more than once in a batch.
- Confirm unknown voltage/connector/wattage never passes safety validation.
- Confirm all stock decisions use recent synchronized evidence or authoritative verification.
- Confirm no credentials are bundled in the submission.
- Confirm actual LLM inference evidence is available as the organizer requires.
- Freeze the exact source and model/prompt configuration that you tested.

A successful HTTP deployment is not the same as a valid competition submission. The final gate is the organizer's local runner and accepted upload.

# Strict allowlisted runtime addendum

The organizer's evaluated Python controller must use Python 3.12.14 and only
the preinstalled allowlisted packages, Python standard library, supplied
helpers, and your own helper code. This strict-runtime package is stdlib-only.
Do not run a `pip install -r requirements.txt` step for the evaluated controller.

Run the local tests with:

    python -m unittest discover -s tests -v

Run the import audit with:

    python scripts/audit_controller_imports.py

The gateway is separate from the evaluated controller. This version also uses
only the standard library: `gateway/server.py` serves HTTP behind the hosting
platform's HTTPS proxy and calls the Gemini REST endpoint with `urllib`. Deploy
it with `python gateway/server.py`; configure `GEMINI_API_KEY`, `GEMINI_MODEL`,
`GEMINI_API_VERSION`, and `GATEWAY_TOKEN` in the hosting dashboard.

IMPORTANT: the evaluated controller must still follow the organizer's exact
`op:llm` lifecycle from API.md. Do not replace that with a direct HTTP request
from `solution.py` unless API.md explicitly instructs you to do so. The
`gateway_client.py` is only a local/manual gateway client.
